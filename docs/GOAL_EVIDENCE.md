## 必要的交集

同一候选架构、固定单折单 seed 下，至少同一组五个数据集必须同时具备：

1. 数据与学生隔离、训练折词表/先验、完整计分人口及相同评估口径证明。
2. Full 独立随机初始化训练正常结束；未使用已训练权重。
3. 全量预测逐键绑定 CSV，重算 AUC 严格超过相应固定门槛。
4. 每个声明保留模块都有从匹配初始状态单独重训的控制。
5. Full 的 AUC 严格高于每个控制，普通及多重比较调整后的学生级区间明确报告。
6. 版本、配置、数据、初始状态、选点规则、预测与进程退出证据相互绑定。

不能从不同数据集分别挑出正向模块，再拼成一个“5/5”结论。
不能通过删除结果不佳的控制、更改统计族大小、删去缺失基线或降低阈值达标。
若模型在数据集间有差异，需事先声明，不能事后拼接最佳结果。

## 基线与统计局限

旧协议明确不重训基线。历史 CSV 是五折均值，部分更强门槛只来自论文数值；
它们不是本次 remap 后的 fold0/seed42 匹配实验。
本地不得把“超过历史参考值”写成“已完成同协议所有基线复现”。
将来若确实需要匹配比较，必须另行审查可用原始基线产物或登记新的执行协议，
不得静默启动或把缺失项计为0。

原 v43 的默认配对审计脚本只覆盖三个旧控制，不能直接用于全模块验收。
本地 v43 拆开两种 SSM 记忆后为11个控制/八数据集族88；
v44 新增历史窗口对照后为12个控制/族96，正式执行包仍未获准。
bootstrap 条件于单次训练和验证选点，不证明跨 seed 稳健性，
也不把持续用于架构选择的 validation 变成 untouched test。

## 数据适用性与容量

服务器训练折元数据 `trainfold_data_summary.json` 显示 Assist2015 和
Statics2011 没有题目 ID。当前题目尝试次数模块只在有效且已出现题目上读出，
在无题目 ID 输入中输出和梯度恒为零。测试 `tests/test_no_item_data.py`
分别检查可训练性与这一零作用边界。因此在不改变模块定义的前提下，
这两个数据集不能证明“所有保留模块严格正向”，不能当成缺失消融自动通过。
这不是把数据集从八个候选中移除，而是暴露当前架构的适用性限制。

另外，Junyi2015 的训练计分交互为16327753，Slepemapy 为6322954；
Slepemapy 有1457个已知概念，当前稠密图每步更新所有概念状态。
Assist2012 有51559个已知题目，需要较大的题目 embedding。
这些值来自服务器摘要，尚未在本地读取对应 CSV 独立复核。

后续需生产形状的资源核查，不能静默缩小模型或删掉模块来宣称达标。
